# Заказы GABILEEN в Telegram

Покупатель открывает каталог в Telegram Mini App, выбирает брюки и размер,
оплачивает заказ на странице ЮKassa и видит статус в разделе «Мои заказы».
Отдельной регистрации нет. Для самовывоза сервис хранит Telegram ID, состав
и сумму заказа, идентификатор и статус платежа. Данные карты вводятся у ЮKassa.

## Подготовка

1. В каталоге задано 3 700 ₽ за каждую модель. Перед реальными платежами
   актуализируйте недоступные размеры в `data/products.json` через поле `soldout`.
2. С аккаунта владельца откройте @BotFather и отправьте `/newapp`.
   Выберите @GabileenShopBot, название GABILEEN и URL
   `https://vanvion.github.io/GABILEEN/`. Когда BotFather запросит короткое имя,
   задайте `shop`. Если оно уже занято в этом боте, используйте фактическое имя
   в ссылке возврата и поле `TG_APP.app` в `index.html`.
3. В кабинете ЮKassa создайте тестовый магазин. Используйте его Shop ID
   и тестовый секретный ключ. На Railway создайте проект из GitHub-репозитория
   `VANVION/GABILEEN` и выберите ветку `main`. В настройках сервиса добавьте
   постоянный Volume с точкой монтирования `/data` и задайте переменные из таблицы.
   В разделе Networking сгенерируйте публичный домен HTTPS. В репозитории
   есть конфигурация сборки контейнера и проверки `/health`.
4. Пройдите тестовый платёж в Mini App. При оформлении покупатель вводит email
   для первого чека, сервер отправляет его в ЮKassa вместе с позициями и сохраняет
   только контрольный отпечаток запроса. Сервер принимает ссылку на оплату только
   для платежа, который ЮKassa отметила как тестовый.

Перед приёмом реальных платежей подтвердите ставку НДС, налоговый режим,
порядок выдачи и второго чека при зачёте предоплаты. Проверьте требования
к маркировке и чек на выдаче товара. Текущий сервис формирует данные только
для первого чека на полную предоплату; выдачу и окончательный расчёт
в производственном режиме ещё нужно подключить.

## Настройки сервиса

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен того же бота, который открывает Mini App |
| `YOOKASSA_SHOP_ID` | Идентификатор тестового магазина ЮKassa |
| `YOOKASSA_SECRET_KEY` | Секретный ключ тестового магазина |
| `RECEIPT_VAT_CODE` | Код ставки НДС позиции по справочнику ЮKassa, согласованный для магазина |
| `RECEIPT_TAX_SYSTEM_CODE` | Код системы налогообложения ЮKassa, если требуется настройками кассы |
| `CATALOG_ORIGIN` | Origin каталога, например `https://vanvion.github.io` |
| `TELEGRAM_RETURN_URL` | Прямая ссылка на Mini App, например `https://t.me/GabileenShopBot/shop` |
| `PICKUP_ADDRESS` | Москва, ТК «Садовод», корпус Б, павильон В50–52 |
| `ORDERS_DB` | `/data/orders.sqlite` для Volume на Railway |
| `BIND_ADDRESS`, `PORT` | Контейнер слушает `0.0.0.0`; Railway подставляет `PORT` |

Запуск из корня репозитория:

```bash
umask 077
node checkout/server.mjs
```

Проверьте `GET /health` через прокси. В настройках ЮKassa добавьте HTTPS URL
`/checkout/webhook` для событий `payment.succeeded` и `payment.canceled`.
Сервис перепроверяет события через API ЮKassa. После этого укажите HTTPS origin
сервиса в `CHECKOUT_API` в `index.html` и публикуйте каталог с той же версией
`data/products.json`, которую читает сервер. Пустой `CHECKOUT_API`
оставляет онлайн-оформление выключенным.

При проверке создайте заказ, завершите тестовую оплату и убедитесь, что после
возврата из ЮKassa заказ отмечен оплаченным. Войдите через другой аккаунт Telegram
и убедитесь, что заказ отсутствует в его истории. Для выдачи сверяйте номер заказа
и оплаченный статус по защищённому доступу к базе. Автоматические уведомления
сотрудникам и учёт остатков по количеству в этот сценарий не входят.

## Развёртывание на российском VPS

Для Timeweb Cloud подойдёт Ubuntu LTS с 1 vCPU, 1 ГБ ОЗУ и публичным IPv4.
Выберите российскую локацию. Привяжите DNS-запись типа A для поддомена оплаты
к этому IPv4, например `pay.example.ru`. Серверу нужны входящие TCP 80 и 443
для HTTPS и исходящий доступ к API ЮKassa. Доступ по SSH оставьте для
администрирования с ключом. Хостинг каталога и Mini App менять не требуется.

Установите Docker Engine с плагином Docker Compose и клонируйте репозиторий.
Создайте защищённый файл настроек вне репозитория, например
`/etc/gabileen/checkout.env`. Впишите переменные из таблицы выше. Путь
`ORDERS_DB`, адрес прослушивания и порт задаёт Compose, их дублировать не нужно.
Затем из корня репозитория выполните:

```bash
export CHECKOUT_ENV_FILE=/etc/gabileen/checkout.env
export CHECKOUT_DOMAIN=pay.example.ru
docker compose -f checkout/compose.yaml up -d --build
curl -fsS "https://${CHECKOUT_DOMAIN}/health"
```

Caddy получает сертификат после настройки DNS. База находится в отдельном
томе Docker `orders`; обычная пересборка контейнера сохраняет данные.
При обновлении кода выполните `git pull --ff-only` и повторите запуск Compose
с тем же именем проекта. Для переноса делайте согласованную резервную копию
SQLite. Не удаляйте тома при обновлении или остановке сервиса.

Платёжный сервер готовится с тестовыми ключами. Публикуйте адрес API в
каталоге только после проверки HTTPS и настроек тестового магазина.

## Команды и уведомления в Telegram

В защищённый файл `/etc/gabileen/checkout.env` добавьте
`TELEGRAM_WEBHOOK_SECRET` со случайным значением из `openssl rand -hex 32`.
Пересоберите контейнер и зарегистрируйте вебхук:

```bash
cd /opt/gabileen
export CHECKOUT_ENV_FILE=/etc/gabileen/checkout.env
export CHECKOUT_DOMAIN=pay.gabileen.ru
docker compose -f checkout/compose.yaml up -d --build checkout
docker compose -f checkout/compose.yaml exec -T checkout node checkout/telegram-setup.mjs
```

Откройте личный чат с @GabileenShopBot, нажмите «Старт» и отправьте `/id`.
Число из ответа сохраните в `TELEGRAM_SELLER_CHAT_ID` в том же файле.
Пересоздайте контейнер командой
`docker compose -f checkout/compose.yaml up -d --force-recreate checkout`.
Продавец видит заказы магазина, остальные пользователи — свои.
`/orders` показывает последние заказы, `/status 54F74A71` — детали и
проверенный статус заказа. Номер берётся из карточки заказа.

Для автоматических уведомлений в тестовом магазине ЮKassa укажите
`https://pay.gabileen.ru/checkout/webhook` для событий
`payment.succeeded` и `payment.canceled`. Сервер перепроверяет события у ЮKassa.
Подтверждённые статусы ставятся в очередь уведомлений SQLite. При недоступности
Telegram сервер повторяет отправку. При сбое сразу после приёма сообщения
Telegram оно может прийти повторно, сверяйте его по номеру заказа.

## Тест гостевой оплаты с сайта

Чтобы включить гостевую оплату на тестовом магазине, добавьте в закрытый
`/etc/gabileen/checkout.env` переменную `GUEST_CHECKOUT_TEST_CODE`.
Сгенерируйте значение командой `openssl rand -hex 16` и пересоздайте checkout.
Код выдаётся только участникам проверки. В обычном каталоге тестовая оплата
не показывается.

Откройте `https://vanvion.github.io/GABILEEN/?checkout=test` в браузере,
выберите одну пару и создайте тестовый заказ. Введите код при первом запросе.
ЮKassa вернёт покупателя в тот же браузер на страницу заказа. Доступ к
истории привязан к случайному ключу в хранилище браузера; ссылка на заказ
сама по себе доступа не даёт. Email используется для чека и в браузере
не сохраняется. Для проверки тестового платежа используйте тестовые реквизиты
ЮKassa и не переключайте сервер на рабочий магазин.

## Тест входа по телефону

В файл `/etc/gabileen/checkout.env` добавьте `TELEGRAM_GATEWAY_TOKEN`
из кабинета Telegram Gateway. Это отдельный ключ. Код доступа
`GUEST_CHECKOUT_TEST_CODE` также должен быть настроен. Пересоберите checkout.

Откройте `https://vanvion.github.io/GABILEEN/?checkout=test&login=phone` в браузере
и нажмите «Мои заказы». Введите номер в международном формате и код из Telegram.
При первом запросе браузер попросит код доступа к тесту. Сессия действует семь
дней. Подтверждённый номер представлен в базе HMAC-идентификатором, одноразовый
код не хранится. Номер передаётся Telegram Gateway для доставки кода.

Новые заказы в этом режиме принадлежат подтверждённому номеру. Прежние
заказы остаются в истории браузера или Telegram Mini App, где их оформили.
Автоматический перенос прежней истории отключён.

### Публичный кабинет

На обычной странице каталога вход доступен без кода тестовой оплаты после
установки `PUBLIC_PHONE_LOGIN=1` и `TELEGRAM_GATEWAY_TOKEN` в
`/etc/gabileen/checkout.env` и пересоздания checkout. Отправка ограничена
60 публичными запросами за 24 часа, с дополнительными лимитами на номер,
браузер и общий поток. Публичный и тестовый кабинеты имеют отдельные истории.
На этом этапе публичный кабинет позволяет войти и просмотреть историю;
создание платежей для него закрыто на сервере.

## Каталог и история заказов внутри MAX

В настройках мини-приложения MAX укажите
`https://vanvion.github.io/GABILEEN/?app=max`. В режиме MAX каталог загружает
официальный Bridge и кнопку «Мои заказы», а форма с кодом Telegram скрыта.
Для проверки подписанной сессии укажите `MAX_BOT_TOKEN` в закрытом
`/etc/gabileen/checkout.env` и пересоберите checkout. Токен относится к боту,
к которому подключено это мини-приложение. MAX, Telegram и вход по телефону
имеют отдельные истории. Для MAX доступен просмотр заказов, оформление через
ЮKassa в MAX пока заблокировано.
